# G0.8 — 门店经营复盘与异常处置（本机合成数据）

## 已完成

- 新增「门店经营复盘」导航：按门店代号筛选、只读运营快照、异常清单、责任员工任务负荷、单机会过程复盘和跳转。
- `GET /api/management/overview?store_id=...`：基于**一条续费机会对应一份来源课包**做单次快照。
- 严格区分当前互斥经营阶段（对照组 / 有关联新净付款 / 仅旧版净付款 / 有合同但无净付款 / 已人工跟进 / 已分配 / 待分配）与独立过程里程碑（任务 / 人工跟进 / 合同 / 净付款）。**过程里程碑可能跳步，不是合格递进转化漏斗。**
- 将关联新合同现金与旧版 `renewals` 分开显示，**不可加总**，防止同一业务在迁移期重复计量；退款及时影响经营阶段。
- 标出待处理异常：逾期活跃任务、机会归档但任务未结束、活跃高优先级未分配、等待超过三天、已付款后净额归零。**不生成对照组额外营销任务**。
- 责任员工仅展示工作量与逾期分布，不冒充绩效评分或排名。经理可从异常/案例跳转到任务与机会，动作继续走原业务API并保留历史。
- 继承G0.7所有原流程；不需要新增数据库表，不变更已有合同、资金和实验事实。

## 已知边界

- 所有数字来自**本地合成演示或去识别化且合法授权的本地数据**，非奥冠真实经营数据。
- 合同、付款与退款UI均为模拟交易，未对接支付商或总账。
- 经营快照不是实时支付流水，不推断**AI因果增量/增量毛利/ROI**。
- 门店/负责人代号只是过滤，**不是授权边界**；当前没有正式登录和角色访问控制，因此服务**不得公网部署或导入未成年人的可识别个人资料**。
- 管理快照最多返回200条案例详情、50条异常详情，`case_count/alert_count`会展示总量。后续真生产版需分页和数据库租户隔离。
- 这个G0.8开发分支基于G0.7，主分支`main`不应合并未安全验收的代码。后续G1重点是登录/RBAC/多租户持久化/隐私治理/真实HTTP E2E。
