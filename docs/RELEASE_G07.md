# G0.7 — 门店销售任务工作台（仅本地合成数据）

## 目的

在G0.6的「识别机会→记录跟进→合成签约→模拟收退款→保留归档」基础上补上真正的日常执行队列：机会分配、截止日、交接、跟进记录、逾期提醒与操作审计。不是自动营销Agent，也不对外提供正式生产服务。

## 交付范围

1. 「销售待办」导航，查看待处理、今日到期、逾期、已结束任务；按门店、负责人代号、截止分桶筛选。
2. 从非对照组且获准营销的**活跃机会**创建任务：一次只关联一张任务，避免重复派单；显示负责人、截止日和原因。
3. 任务工作台操作：负责人交接、改期、人工记录联系状态与结果、完成/取消、操作历史；旧机会详情跟进入口与任务状态保持一致。
4. 任务和机会状态分离：已经成交并归档的机会，原任务和操作历史仍可查看、可人工关闭，但**不得再次发起新的产品营销跟进**；全额退款且机会重获资格时，可填写原因重新打开原任务。
5. 所有任务、事件按原本地SQLite数据库持久化；演示数据重置会同时清空任务与事件。
6. 继承G0.6：合成合同、收款、退款不是真实交易；任务完成不等于客户续费，更不等于AI增量效果。

## API

- `GET /api/tasks?store_id=...&owner=...&status=...&due_bucket=...` 返回 `items` 和任务概览；注意 `owner` 仅是**筛选代号**，不是登录用户，也不构成访问控制。
- `POST /api/tasks` `{opportunity_id,owner,due_on,note?}` 创建业务任务。
- `PATCH /api/tasks/{task_id}` `{actor,owner?,due_on?,status?,note?}` 记录转交、改期与关闭。结束或重新开启必须填写原因；已归档的机会不可重新开启。
- `POST /api/tasks/{task_id}/followups` `{actor,status,note?}` 在同一事务中保存跟进与任务变更；允许旧 `POST /api/followups` 更新对应活跃任务。
- `GET /api/tasks/{task_id}/history` 返回追加式事件历史。

实验保护：对照组与未授权客户没有任务创建权限；不可向已归档机会增加定向营销跟进。

## 验收与证据

- `python -m pytest -q`：G0.2～G0.7共**71项**本地测试（升级、任务闭环、历史保留、对照组保护、模拟收退款、旧接口同步）。
- `node --check static/app.js`：浏览器JS语法检查。
- `python scripts/dom_smoke_g07.py`：可选，需系统Chromium+Playwright。浏览器以**模拟API**交互，测试机会→创建任务→待办详情。它不是后端HTTP端到端测试；当前云浏览器对本机HTTP存在管理层拦截。
- CI：Python3.11/3.12自动回归测试，必须取得GitHub Actions成功结果再算远端合格。

## 仍然不能上线

**绝对不要合并到现有公开Vercel部署的main分支。** 当前没有账户登录、角色授权、门店隔离、敏感信息访问审计、个人信息生命周期、PostgreSQL持久化、安全部署与真实支付核验。现有Host限制必须保留。合成任务不属于真实经营ROI。针对生产环境需另立G1安全/数据架构里程碑。
