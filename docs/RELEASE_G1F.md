# G1-F｜真实Chromium端到端验收（仅CI合成环境）

## 范围与目标

使G1-E已验证的HTTP API与PostgreSQL真实数据库，经**浏览器加载实际页面、用户点击、表单提交**完成完整续费经营闭环。G1-F不是公网部署许可。

运行路径：Playwright Chromium → `http://127.0.0.1:<ephemeral port>/` → Uvicorn/FastAPI → 独立身份和业务 PostgreSQL 连接 → PostgreSQL 16。

## 验收用例

1. 浏览器真实加载 `/`、登录经理、选择授权机构和门店并刷新机会。
2. 经理使用页面分配员工任务；任务在“销售待办”可见。
3. 未分配的同门店员工看不到该机会；员工进入本人机会并记录跟进，不能看到经理财务详情或进入经理复盘。
4. 经理在界面创建合成合同，登记模拟付款与退款，经营复盘净额与交易事实一致。
5. 经理在UI里尝试切换到无权限机构，被拒绝且旧列表清空；另一机构经理同名门店只能看到自己的数据。
6. 退出后回到登录页面；单次运行不得出现5xx业务API返回。
7. 所有数据是测试脚本当场创建的合成ID；只在一次性CI数据库执行；浏览器运行失败时保存截图（不导出包含登录密钥的HTTP traces）。

## 运行门槛

- CI使用PostgreSQL 16，依次应用001/002/003迁移并建立独立身份与业务角色。
- `pytest`仍在Python3.11/3.12运行；真实Chromium仅在Python3.11的CI job执行，以减少重复浏览器下载。
- 浏览器依赖由GitHub Actions单独安装，CI调用`python -m scripts.browser_http_e2e_g1f`。
- 测试进程必须同时具有`CI=true`和`RENEWAL_PG_CI_BOOTSTRAP=I_ACCEPT_CI_ONLY`，否则直接拒绝执行。
- 本地浏览器环境导航被管理员策略拦截，不代表可在本地完成此验收；必须以CI实际运行结果为准。

## 本轮修复

- 对普通员工隐藏经理专属复盘标签；仅隐藏UI不代替后端权限校验。
- 当机构/门店输入不属于当前会话授权时，刷新给出明确错误、清空过期列表，而不是产生未处理的浏览器脚本异常。
- 退出时重置所选功能页及会话内操作状态，防止不同账号沿用上次经理的页面状态。

## 没有完成的生产条件

本版本仍是`secure_local`合成演示：没有OIDC/SSO/MFA正式登录、正式开户流程、实际收款来源验证、客户授权、儿童数据合规、备份恢复、可访问的云端生产服务或完整网络安全验收。

**CI通过 ≠ 生产上线许可；模拟合同与收款不代表真实经营收入，AI也未被证明增加续费率。**
